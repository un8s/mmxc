# UI translation

MMXC's interface is written in English and translated at runtime by your
configured LLM. There are no per-language source files to maintain: pick a
language, and each UI string is translated the first time it is shown, then
cached on disk.

Your *data* is never translated. Account, category, and payee names are your own
content, and currencies come from your database.

## Using it

In **Settings → Translation** (or in `mmxc.yaml`):

| Key | Meaning |
| --- | --- |
| `translation_language` | ISO 639-1 code (`de`, `fr`, …). `en` or empty disables translation. |
| `translation_model` | Model used for translation. **Empty disables translation** even if a language is set. |
| `translation_dir` | Cache directory (default `data/translations`). |

The translation model is separate from `llm_model` on purpose: translation wants
a small, fast model (e.g. `translategemma:4b`), the assistant and statement
import want a capable one. It uses the same endpoint (`llm_base_url`).

There is no `Accept-Language` negotiation and no environment overrides: this is a
single-user app, so the Settings dropdown is the language switcher.

## How it works

`pageData.T(source, guidance…)` (`main.go`) is the one entry point, backed by the
`translator` in `translate.go`.

- **English is identity.** For `en` no model is called and the source is returned.
- **The English text is the key.** Entries are stored under
  `hash(source + guidance + lang)`. Editing an English string therefore
  re-translates it (the old entry is simply orphaned); there are no ids to
  maintain.
- **Guidance disambiguates.** The optional second argument says where a string
  appears (`{{.T "Balance" "account balance column"}}`). It is sent to the model
  as context and is part of the hash, so the same English word used in two senses
  gets two cache entries.
- **Cache first, then the model.** A hit returns the cached text. A miss makes one
  synchronous LLM call (temperature 0, JSON mode), stores the result, and rewrites
  `<translation_dir>/<lang>.json`. Misses are not batched, so the first page load
  in a new language is slow (one call per unique string); later loads are all hits.
- **Failure falls back to English.** No model configured, endpoint unreachable, a
  bad response, or a rejected translation all return the English source. The UI
  never blocks on or breaks because of the model. Failed translations are not
  cached, so they are retried on the next load.

### Guards on model output

A translation is rejected (and English shown) when:

- its `%s`/`%d`/… placeholders differ from the source — they are later passed to
  `fmt.Sprintf`, so a garbled one would be a runtime bug;
- it is implausibly long (`plausibleTranslationLength`: more than 4× the source
  plus a constant slack). This catches the model translating the prompt or the
  guidance line instead of the string. The source and guidance travel as labelled
  JSON fields (`{"source": …, "context": …}`) for the same reason.

Named placeholders (`{n}`, `{cat}`) are preserved via the prompt only; they are
not validated.

## Correcting a translation

The cache is plain JSON, and each entry records what it translated:

```json
"3f9a1c0b7d2e4a55": { "source": "Balance", "guidance": "account balance column", "translation": "Saldo" }
```

Edit the `translation` value to fix a clumsy machine translation. MMXC notices
the changed file (it checks at most once a second) and uses the edit on the next
page load, no restart needed. The file wins over memory: delete an entry to have
it translated again. If you save invalid JSON, MMXC keeps the translations it
already holds until the file parses again.

## Adding or changing UI text (for developers)

Every user-visible string must go through the translation layer:

- **Templates** (`assets/templates.html`): `{{.T "text"}}` or
  `{{.T "text" "guidance"}}`. Inside a `range` or a sub-template use `$.T` /
  `$root.T`. Give guidance for short or ambiguous labels (`Amount`, `Type`,
  `Status`, `Balance`, `Split`, `Void`, …) and for strings with placeholders.
- **JavaScript** (`assets/app.js`): strings can't be translated in the browser,
  so they are injected as `window.MMXC_T` by a `<script>` in the `head` template
  (`"Some text": "{{.T "Some text"}}"`) and read with `i18n(key)`, `i18nf(key,
  {name: value})` (named `{x}` placeholders) or `i18nfmt(key, …)` (positional
  `%s`). Add new strings to that map or they will stay English.
- **Go**: fixed validation/guard messages go through `a.httpError(w, msg, status)`
  (which picks default guidance via `httpErrorGuidance`; extend it for new message
  families) or `a.translateUI(source, guidance)`.
- **Deliberately not translated:** dynamic `err.Error()` text and interpolated
  compatibility details. They are technical, and translating them would put an
  LLM call on the error path.

## Dates and numbers

- **Dates**: `{{.DateFmt .Date}}` reformats a stored `YYYY-MM-DD` for **display**
  using `localDateLayout` (`helpers.go`): e.g. `02.01.2006` for German,
  `02/01/2006` for French, ISO for English and the Nordic languages. Form
  `<input>` values must stay ISO so they round-trip — never run them through
  `DateFmt`.
- **Money** is driven by the **base currency**, not the UI language. At startup
  `loadBaseCurrencyFormat` reads the prefix/suffix symbol, decimal point, group
  separator and scale from `CURRENCYFORMATS_V1`, and the `money` template func
  formats with that. Switching UI language does not change how amounts look.

## Not supported

- **Right-to-left layouts.** Arabic text is translated, but the layout is not
  mirrored.
- **Curated, human-reviewed catalogs.** All translations are machine-generated
  into your local cache. Nothing ships in the binary; if you'd like to share a
  corrected `<lang>.json`, it can be dropped into `translation_dir` as-is.
